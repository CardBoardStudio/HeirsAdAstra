# Streamlined Operations release contract

The canonical rules establish five queued changes at `#resources`, `#storage-allocation`, `#construct-two-builds`, `#movement`, `#building` and `#combat` before implementation. Excess of each resource is automatically discarded after every gain, with no pending choice. Capacity allocation defaults to one point each and remains editable. Construct II permits two sequential full-cost builds in one action, with an explicit optional finish after the first. The card commits once on the first successful build; the second choice persists through saves, Undo, reports and replay. Conversions and free resource management remain available during that continuation. Advanced construction cards keep their existing reference behavior.

Remove the per-hex ship limit from movement, construction, retreat, escape and both rival policies; faction-wide limits remain Settlers 8, Explorers 5, Fleets 10. Remove occupation state and all associated production/building restrictions and messages. Enemy units and enemy Shipyards still defend; passive ownership does not trigger a battle. Ownership changes only through Colonize with a Settler and 1 Biomass on an undefended enemy center. Existing combat scoring stays unchanged.

New games use format 29, rules 34 and native policy 25. Preserve the exact 28.33 browser, canonical manual, native policy 24 and prior archives, with pinned table/replay routes and no save migration. This is a separate breaking PR into main; the user explicitly authorized implementation, merge and publication. Desktop-only visual/accessibility checks cover the continuation controls, automatic capping, capacity defaults and large ship stacks. Verify source/packaged rules, meaningful current mechanics/dialog/replay tests, native workspace/fmt/Clippy, Wasm and container CI, successful exact-head Render preview and stable deployment.

Verification: 30 JavaScript suites, including 56 real-app fake-DOM browser-flow checks, source rules checks, native workspace tests, formatting and Clippy passed locally. Dedicated current-rule tests cover caps, losses, all 35 capacity allocations, free relic allocation, full-cost two-build continuation, mixed/different-site builds, resource management between builds, failed/forged actions, faction versus hex limits, large-stack escape, enemy production, capture, and frozen archives. Nine exact-source desktop scans have zero axe or supplementary contrast failures; see `tools/accessibility/streamlined-operations-results.json`. CI and exact-head Render preview verification are required before adoption.
